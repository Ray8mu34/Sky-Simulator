# 第八批实施构想：数据扩展与插件边界

记录日期：2026-10-21；2026-10-25更新。状态：10等HYG星表已实现，其余条目为后续设计。

## 当前推进决定

v0.2.0已完成版本提示和教学资料保存。按最新会内使用需求，后续优先功能交付；上线前保留构建检查和桌面Chrome、Edge、浏览器窄屏关键流程，不再将持续长测、实体手机或其他浏览器作为每批交付前提。

v0.3.0先实现有界的10等HYG目录：保留8,921颗基础星，追加99,150颗，合计108,071颗。通过40字节记录和稀疏元数据随Web/便携版一起发布，无需在线加载分片。星图深度默认6.5等，可调整至10等；进入肉眼模拟恢复6.5等。编号搜索、详情、定位和设备视场直接复用现有路径。完整目录仍有选择效应，不能当作10等完备星表。

此规模尚不需要百万星目录的分片/LRU系统。数据增加后Web压缩预算调整至6.5MB，原始包12MB、便携版16MB预算保留。新增星沿用现有自行模型，渲染位置按30日缓存；选中标记与详情使用当前时刻。基础目录既有缓存精度界限不扩展声称覆盖新增星。

后续若重点是望远镜寻星/摄影构图，优先用小规模分片星表补足现有窄视场；若重点是航天科普，优先精选空间站/卫星。小天体按具体专题需求安排，通用扩展接口在至少两个真实扩展模块后提取。下文保留各项技术边界，不表示已排入实施。

## 目标与顺序

各项独立发布，按上面的实际用途选择先后；避免同时改写星历、资源管理和渲染管线。

### 1. 人造卫星

采用成熟SGP4库，首版支持本地轨道数据导入、ISS等精选目标、过境轨迹、地影和太阳照明。输入同时考虑TLE与支持更长目录编号的OMM/JSON格式，见[CelesTrak说明](https://celestrak.org/NORAD/documentation/gp-data-formats.php)。第二步才接在线更新。轨道数据必须保留历元、来源、获取时间，不以当前日期包装旧轨道。TEME到地固/站心转换与UTC时间口径需要独立参考验证；上方、受光、天色足够暗应是三个分别可见的条件，不合成为无根据的“可见”。

验收：已知TLE样例的传播位置、坐标变换、地影进出、极区与跨午夜过境；断网下旧数据仍可查看并显示年龄；损坏数据不得污染已有目录。

### 2. 彗星和小行星

先支持有来源的轨道根数、历元、位置、搜索、详情和多日轨迹；再增加彗尾示意。分开处理椭圆/近抛物线/双曲轨道，不将简单双体传播宣称为高精度长期星历。视位置包括光行时、地心/站心转换；亮度参数允许缺失，彗星活动不可用固定公式保证。

验收：对照固定JPL Horizons样本，统一时间尺度、参考系和光行时；跨近日点、e≈1、双曲轨道、无亮度参数。

### 3. 大星表

现在的约9千颗亮星目录保留为基础包。新增按天区（HEALPix或等价分片）与星等层级组织的二进制数据块；相机视场和极限星等决定请求。搜索索引与可见星点数据分离，标识符稳定。

必须先做资源管理：有界LRU、并发上限、取消/代际标记、防止快速拖动造成过期回写；CPU/GPU缓存分别计数；切换地景/设备不应重复下载星表。分片包含版本、记录数、哈希和许可。

交付建议：基础单HTML继续独立离线；Web提供可选目录包；扩展离线版用目录包或本地资源存储，不将百万星目录无条件嵌入单HTML。缓存失败时回到亮星包，并明确额外星表未就绪。

验收：移动设备内存峰值、连续缩放/转向、断网与部分包损坏、首次加载与缓存升级、目录交叉编号去重；不得只以桌面帧率作为完成依据。

### 4. 扩展接口

至少完成卫星和小天体后再抽象共同接口：对象身份/搜索、科学方向计算、详情字段、轨迹采样、渲染批次、来源与许可。内核保留唯一时钟、观测者和快照，不让插件复制时间状态。

第一版宜为构建时受控模块及声明式数据包；任意远程脚本插件、动态权限系统和第三方UI注入暂不纳入。新增对象ID命名空间与场景版本迁移需要显式策略。

## 与第六、第七批的接口关系

- 课程使用完整场景快照；扩展对象缺失时应提示所需包，不悄悄换目标。
- 相机/目镜小视场会暴露亮星目录稀疏问题，这是大星表的主要用户价值。
- 地景包当前独立导入导出；后续可和课程、星表一起纳入有哈希的资源清单，但避免把图片复制到每个课程步骤。
- 自定义真实地平参与升落求解，应独立增加地平高度函数与事件定义版本，不与星表扩展混在同一批。

## 开工前需要决定

目标星数和最低设备内存；数据许可与分发方式；TLE/小天体更新源及跨域可用性；基础HTML体积上限；可选资源包的版本、迁移、缓存清理和离线导入方式。先用小规模分片原型测量，再锁定规模。
